CHIMERA RX REVIEW FOR PRITESH
November 22 2026 | upstream main 30408a6

Pritesh, the latest build has substantially more functionality and useful test coverage. We recommend closing the five P1 defect groups below before expanding the pilot. The main risks are an overwritten pharmacist hold, incomplete cross-store recall blocking, alternate clinical read paths, missing local-sale alerts and interrupted transfers. The attached tests reproduce them against upstream 30408a6 without touching the running demo.

Read review.html for the formatted report. Source references are pinned to the reviewed commit.

F01 P1 - Automatic review overwrites a pharmacist hold
Evidence: Deterministic concurrency reproduction
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/rxwatcher.ts#L233 | apps/api/src/fill.ts:99
Reproduce: Start scanFill for Rx 0072214 with review=none and pause the model response. While paused, submit a valid pharmacist change request; confirm review=on_hold. Release the model. The review becomes clear and the scan fills the order.
Impact: A pharmacist decision made during an automatic review is lost, and an order awaiting a prescriber change can proceed to filling.
Implementation: Persist automatic findings using a conditional update against the current order version and review state. Revalidate review and version inside the fill transaction. Do not rely on the review value read before an await.
Acceptance: The hold and change-request record survive model completion; the scan returns a conflict and creates no dispense. Repeat with reject, approve, order edits and simultaneous review runs.

F02 P1 - Pending destination recall prevents confirmation from propagating
Evidence: Two-store acceptance reproduction and successful fresh-destination control
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/crossstore.ts#L84 | apps/api/src/recall.ts:153
Reproduce: Store 2 looks up D-0611-2026 without confirmation. Store 7 then looks up and confirms it. Store 2 retains confirmed_at=null because INSERT OR IGNORE preserves its existing pending row.
Impact: The other store can continue to hold affected packages on the shelf despite confirmation at Store 7. The current test covers only a destination without the pending row.
Implementation: Merge confirmation into an existing pending recall-lot row, with provenance and audit, before quarantining. Treat propagation as idempotent and retryable.
Acceptance: Both a fresh destination and a destination with a pending row end with GX4471C confirmed, zero on-shelf affected packages, and receiving/fill/register/transfer blocks. Repeat confirmation and restart must not duplicate work.

F03 P1 - Clinical reads bypass cashier and admin role restrictions
Evidence: HTTP reproduction plus ten failed role acceptance checks
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/agents/routes.ts#L107 | apps/api/src/agents/routes.ts:118; apps/api/src/app.ts:219,228,249
Reproduce: After a pharmacist runs Guardian and confirms a recall, sign in as cashier m.diaz or admin s.grant. GET /api/agents/runs, /api/agents/rx-guardian, /api/recalls, /api/recalls/D-0611-2026 and /api/recalls/D-0611-2026/results. Each returns 200. Agent output contains patient IDs with clinical history; recall output exposes patient-linked impact or outreach information. /api/suggestions correctly returns 403.
Impact: Hiding clinical screens and protecting the patient endpoint does not protect alternate reads of the same data.
Implementation: Define an explicit read authorization matrix. Gate clinical run history and recall patient details; return a separate minimal summary where a role needs counts. Filter by agent and role before serialization.
Acceptance: Anonymous reads return 401. Cashier/admin clinical detail reads return 403, or an explicitly specified sanitized summary without patient-linked clinical data. Pharmacist and permitted technician reads still work. Cover all downloads, audio, search, nested results and partner scopes.

F04 P1 - Current locally sold medicines are omitted from some safety rules
Evidence: Pure-rule comparison with a passing Active control
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/agents/guardian.ts#L115 | apps/api/src/agents/guardian.ts:173,262; apps/api/src/rxwatcher.ts:63,195
Reproduce: Evaluate a ciprofloxacin order with a two-day-old 68-day insulin fill. With history.status=Active the Guardian emits its fluoroquinolone/insulin demo-table interaction. Change only status to Sold here, the status loadHistory assigns to local dispenses: no hit is emitted.
Impact: A new local sale can be present in history but absent from interaction or duplicate-therapy evaluation. This finding demonstrates software inconsistency, not clinical accuracy of the synthetic rule.
Implementation: Unify active-medication derivation across imported history, local dispenses, Watcher and Guardian using supply dates and discontinuation state. Avoid merely changing every historical sale to Active.
Acceptance: Receive/fill/verify/sell an unseeded current medicine, create the next relevant order and verify the expected demo rule. Include expired supply, discontinued medicine, duplicate imported/local history and corrected orders.

F05 P1 - Interrupted cross-store transfer duplicates available stock
Evidence: Injected source-write failure after destination commit
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/crossstore.ts#L40 | apps/api/src/crossstore.ts:54
Reproduce: Select an on-shelf AMX0626C package. Inject a source database trigger that aborts its transfer-out update. Transfer one unit to Store 2. The operation throws, but the destination has already committed. The serial remains on_shelf in both stores.
Impact: The same physical serial is offered as available twice. A user retry does not provide an explicit reconciliation or durable transfer state.
Implementation: Use a durable transfer ID and state machine with a source reservation, idempotent destination receipt, commit acknowledgement and recovery/reconciliation. A local transaction around one database does not make two files atomic.
Acceptance: Inject failure before and after each write boundary, restart and retry. At most one store can offer the serial. Incomplete transfers remain visible and recoverable, with consistent audit records.

F06 P2 - Store 2 outputs retain Store 7 identity and contact details
Evidence: Source inspection; manufacturer-response improvement acknowledged
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/recall.ts#L215 | apps/api/src/recall.ts:217-225,238-242,364
Reproduce: Use Store 2 to draft default recall outreach or generate its recall PDF. Templates hardcode Elm Street, J. Rivera and Store 7 phone; the PDF heading hardcodes Store 7. Store 2 has a different name, pharmacist and phone.
Impact: A correctly scoped patient list can still produce a misattributed report or direct a recipient to the wrong pharmacy.
Implementation: Resolve pharmacy name, phone and signing actor from the current store at draft, preview, send and export time. Review voice templates and AI draft merging too.
Acceptance: Store 2 previews, sandbox sends and PDF use Birch Avenue, its own contact details and the approving actor. Store 7 remains correct. Do not count the fixed manufacturer-response path as coverage for all outputs.

F07 P2 - Provider destination policy accepts mapped link-local addresses
Evidence: Provider-settings API accepted the URL; no metadata request made
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/agents/routes.ts#L30 | apps/api/src/agents/providers.ts:102-109,320,353
Reproduce: As an authorized pharmacist/admin, set baseUrl to http://[::ffff:169.254.169.254]/latest. The API returns 200 although literal 169.254 addresses are rejected. The settings were restored after this test.
Impact: The intended metadata-destination block is incomplete. Exploitation depends on configuration privileges, connectivity and the adapter POST path. Credential theft was not demonstrated.
Implementation: Normalize and validate IP families and resolved destinations, including redirects. Make permitted local-model endpoints explicit. Bind stored credentials to approved origins when endpoints change.
Acceptance: IPv4, IPv6 mapped addresses, hostname resolution and redirect cases follow the same destination policy. Rejected destinations receive no request or credential. Intended localhost model endpoints remain usable.

F08 P2 - Windows file-key permissions do not meet the owner-only claim
Evidence: Three Windows permission test failures and inspected generated-key ACL
Source: https://github.com/KoinArc-Labs/Chimera-Rx/blob/30408a6/apps/api/src/crypto.ts#L120 | apps/api/src/crypto.ts:124,131-135; docs/SECURITY.md
Reproduce: Run the file-key provider on this Windows host. POSIX mode assertions report 0666 rather than 0600. The generated key also inherits a read grant to the local CodexSandboxUsers group in addition to the owner, SYSTEM and Administrators.
Impact: chmod does not establish the claimed owner-only boundary on this platform. This is not evidence of public access.
Implementation: Define supported deployment platforms and enforce an appropriate Windows DACL, or require externally supplied keys on Windows. Document and test the actual access boundary.
Acceptance: An unauthorized local account cannot read the current, retired or temporary key files. Tests validate Windows ACLs on Windows and POSIX modes on Linux. Key rotation and restore still work.
